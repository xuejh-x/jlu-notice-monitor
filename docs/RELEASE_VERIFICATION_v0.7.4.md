## 安装包

- Windows x64 NSIS：`JLU Notice Monitor_0.7.4_x64-setup.exe`。
- SHA-256：`8e20dcc9171f2cdb8c5cbb7d2c45f612c81069929656e8e514e0d84664ef5786`。
- 同时上传对应 `.sha256` 文件；GitHub 会将资源名中的空格规范化为点。
- Authenticode：NotSigned，没有把 SHA-256 当成代码签名。
- 打包/安装后端 SHA-256 一致：`baa8504034b515e6e610551ddeb34a8baa4cd0f22701ab5d00fa6b31fd8dbbc4`。

安装后主程序与裸构建 EXE 的差异只有 Tauri bundle type 的三个字节：安装包为 `NSS`，构建完成后裸程序恢复 `UNK`；其余字节相同，大小与 0.7.4 PE 版本一致。因此未以裸构建哈希不相等就错误认定安装失败，也没有跳过差异核对。

打包检查最初错误要求仅供离线审计的 `attachment_validation` 前缀分类模块也进入客户端；该模块无应用运行引用。改为检查真实运行依赖后，实际 sidecar 启停及公开页面检查通过，没有降低运行模块或数据隔离要求。

## 发布内容与限制

源码提交包含当前应用、测试、构建与审计工具，以及必要的版本、设计和修复报告。原始抓取 HTML、运行日志、机器完整证据、数据库、凭据、私有备份、安装器和开发环境不提交到 Git；安装器仅作为 Release 资源上传。原报告中的本地证据路径可能不随公共源码存在。

首次推送准备被自动审批拦截，原因是包含静态 TLS 测试私钥。已从提交范围移除私钥及对应静态证书，原文件仍保留本地；TLS 回归现在只在 pytest 临时目录生成新密钥和证书，不安装到系统信任库。公开暂存版本扫描未发现私钥路径或私钥内容，且完整回归通过后才继续发布。

新增候选未启用，OA 默认网络路径、权限/验证码限制、招生日期语义、全历史分页和真实 Cloud 准入仍按专项报告保留。没有新增自动更新服务、部署 Cloud 或修改系统网络。

本次安装验收使用独立数据启动桌面程序，未让正式库执行自动抓取或启动清理。用户随后正常启动仍适用既有保留策略；备份不等于承诺过期记录永久保留。Windows 原生通知弹出和所有生产来源联网不是本次发布验收通过范围。
