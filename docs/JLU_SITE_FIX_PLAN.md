## 1. 目标与事实基线

先保证现有来源抓取正确，再适配高价值公开栏目，最后按 CMS 模板扩展学院及其他机构。成功标准是通知语义、数据保护和实际运行环境通过验证，不是候选数量增加或 HTTP 返回 200。

依据：[专项审计](JLU_SITE_AUDIT.md)、[逐栏结果](jlu-compatibility-report.csv)、[站点清单](jlu-site-inventory.csv)、`jlu-audit-evidence/results/`、[TLS 专项](HTTPS_CERTIFICATE_FIX_REPORT.md)及同期 OA 诊断证据。

| --- | ---: | ---: | ---: | ---: | ---: |

293 个适配对象完成过有限抽样；13 个引用不是新增来源对象。164 个站点主机、305 条尚未确认独立官网的机构记录，分别属于站点发现和组织清单口径。不能据此承诺全校历史覆盖率。

问题标签允许重叠，不代表独立来源数：189 个栏目未配置分页、108 个栏目附件端点未验证为文件、77 个栏目列表日期缺失、40 个栏目出现标题不一致、27 个栏目疑似误抓导航、14 个栏目空结果、11 个栏目可见附件未提取。

## 3. 各批次实施内容

### B0：基线与证据准备

- 固定实施前 Git revision、工作区相关文件 SHA-256、来源配置、测试结果和证据时间。已有未提交 TLS/HTTP 诊断修复先识别、复用，不覆盖或重复实现。
- 从审计快照提取最小、脱敏 HTML fixtures，保留列表、对应详情、分页和附件样本之间的关系。优先覆盖既有 8 个栏目，再加校级、学工、就业和一个确为空的栏目。
- 审计工具补充独立输出目录/新运行标识，明确区分缓存重放和实时复验；不直接使用旧目录的失败缓存来宣布修复仍失败。旧证据保持不变。
- 将每个问题标成：已证实解析错误、访问/TLS 阻塞、历史覆盖能力边界、尚未核验。`ATTACHMENTS_UNCHECKED` 不是损坏证据；分页缺省首屏也不直接等于日常漏抓。
- 235 passed、1 skipped 是审计时历史基线；实施前使用隔离环境重新取得实际数字。不要因环境变量覆盖默认值而把测试环境断言失败算成产品回归。

验收：每项首批修复都能离线复现；测试与复验只能写入内存 SQLite 或独立临时数据库，入口执行前验证路径不指向正式资料目录。

### B1：先阻止错抓和错误预览成功

涉及文件：`backend/app/parsers/html.py`、`backend/app/sources/generic.py`、`backend/app/api/source_management.py`；必要时使用 `sources/base.py` 和 runner 既有的逐通知异常处理，不重构来源注册或调度架构。

1. 列表解析限定在可证明的通知列表容器；排除导航、面包屑、分页、友情链接和非法 href。未知模板应要求选择器配置，不能只凭 .htm/.html 后缀提升成通知。
2. 区分“有效但当前为空的栏目”和“选择器失效/模板未知”。两者都不得生成导航候选；预览沿用现有失败响应契约表达具体原因，不给不合格公开来源签发成功 preview token。
3. 详情不能仅凭整页 body 非空通过。结合模板容器、标题、正文/合法附件内容判断；导航、登录页和错误页不得当正文。短通知、附件型通知不能只按字符阈值误拒绝。
4. 通用预览与实际抓取使用一致的内容检查，避免只在预览拦截、crawler 仍写入同类错误。复用 runner 的单条失败隔离：其他有效通知可继续，无效详情不能覆盖已有通知或推进该条成功基线。
5. SafeFetcher 保留原始异常 cause/context，并复用现有诊断/脱敏规则。区分 EOF、连接/读取超时、HTTP、TLS 与 robots 受阻；日志不暴露 Cookie、凭据或敏感 query，不更改通知 URL 中有身份意义的参数。

验收：27 个疑似导航栏目中的代表样本不再产生导航通知；有效空栏目无伪候选；登录/错误页面不产生成功预览；既有正常样本和 11 个通过样本作正向对照；单条错误不抹掉已读/收藏或既有正文。

### B2：标题、日期与正文

- **校级通知**：适配实际 `.nr_title`，剔除其中作者、时间等元信息，恢复 `info/1095/58176.htm` 的完整标题；不把全局栏目标题或任意 h2 当文章标题。
- **学工通知**：从独立日期节点组合日、年月，不从 li 摘要寻找第一个完整日期。`xsc.jlu.edu.cn/info/1048/5941.htm` 应取发布日期 2026-10-13，不能取摘要公示起始日 2026-10-12。
- **其他 VSB 模板**：优先解析明确发布元信息，补拆分日期与标题容器；缺失日期保留缺失，不根据抓取日期、活动日期或截止日期编造发布日期。对日期冲突保留证据。
- **CSE 空正文**：先核对原网页是否有图片、附件、外链或确为空。图片型通知保留合法原始 HTML/图片链接并在现有内容路径中验证；不要用导航、标题复制或自动生成文字填充正文。确为空则隔离并报告。
- **食品学院编码**：针对 `spxy.jlu.edu.cn/bksjy/jxxx.htm` 的替换字符检查响应头、meta 声明与原始字节。只有复现编码错误才修解码；若是站点源数据损坏则保留异常，不能盲目反复转码。

验收：列表与详情的完整标题、发布日期逐条对照；覆盖跨月/跨年、置顶旧通知、摘要含截止日期、短通知、图片型/附件型通知。修改公共解析函数时，五个薄适配器及 OA 专用解析器都要回归。

### B3：附件可靠提取与访问分类

- 优先补软件教办 `csw.jlu.edu.cn/info/1095/8548.htm` 的六个 jpg 附件；从明确附件容器识别文件，按实际样本扩展图片、压缩包、演示文稿白名单，避免把站点 logo 或正文普通导航当附件。
- 保持 `filename / url / type` DTO，完整保留 VSB download.jsp 的查询参数。按 URL 去重，对文件名和类型做可解释归一化；不执行、解压或批量下载文件。
- 108 个附件端点问题逐步区分为：可获取文件、合法下载说明/验证页、认证/验证码限制、失效链接、尚未确认。Range 返回 HTML 不能推断“附件已坏”，200/206 也不能推断“下载已成功”。
- 对受限下载保留原始合法入口；不绕验证码、不引入未经授权的登录。暂不新增前端字段/页面；确需展示下载状态时，另立 API/UI 方案并遵守 Design Contract。
- OA 附件继续用专用编码规则。先验证已有 fixture 的 POST/响应错误处理，再在公开、无认证、允许访问的真实附件样本上有限验证；未实际验证的链路保持未验证状态。

验收：可见、合法的样本附件数量与文件名一致；非法或私网 URL 仍被拒绝；下载页不会假装文件；其他附件样本未检查时明确保留未检查，不为提高通过数隐藏告警。

就业网优先尝试现有高级选择器，只有配置无法正确表达时才加小型专用 adapter。通知/公示通过不等于招聘、实习和全部职位接口已通过；这些未覆盖栏目先发现、记录再验证，不凭名称自动新增来源。

验收：每个实际启用的栏目至少核对 3 条详情（不足 3 条则全检并注明）及一个有附件的样本（若存在）；公共数据、栏目语义、日期和附件状态符合 B1–B3。配置先放独立候选文件/测试配置，不在此批批量改正式 YAML。

### B5：分页、去重及运行环境准入

**分页采用两个范围。** 日常增量抓取先明确每轮最多 1–3 页、最多条数和停止条件；需要补历史时使用独立、显式、可暂停的补抓任务，不能将初始化变成全站无限抓取。复用现有 next_page_selector 能力，StaticHTMLSource 的扩展采用显式配置，既有配置缺省行为保持兼容。

检查禁用下一页、重复页、循环链接、跨域跳转和栏目边界；明确分页上限/条数上限之间的关系，不能抓三页后又截断成第一页条数，却宣称三页已覆盖。页内/页间 URL 去重，但不因第一页全是置顶旧通知就提前停止而漏掉后续新通知。

**去重先复现再调整。** 113 组同 URL 和 48 组同标题/日期是候选证据，不是已确认数据库重复。保留来源关系、规范 URL 和 public_id；协议别名只有可证明等价才合并。不全局放宽标题相似度，不仅凭同名/近日期跨站合并不同通知。

标题/日期纠正可能触发现有 14 天/0.92 相似匹配边界，要用隔离旧数据验证不会创建重复通知或错误合并；不能为修复内容清空数据库、重置 ID、已读、收藏或 baseline。确需一次性历史修正/迁移，另给可审查方案，本计划不授权直接执行。

**分别验收环境。** 本机 Windows、实际 Cloud Linux 的 TLS/网络/安全、Cloud feed 和 Desktop fallback 分开记录。Fake-IP 下的本地结果不能替代 Cloud DNS 安全验证；Cloud 证书链或网络不通时不关验证、不放行私网地址。保留 cloud_preferred/cloud_only/local_only、source ownership、订阅与调度策略。

OA 以较新恢复证据为起点复核：匿名默认路径、公开列表、至少两条详情、重复刷新、健康状态和用户状态保持；Cloud feed 地址未配置仍记未配置，不记云抓取成功。已有 TLS 工厂和 HTTP 诊断修复只补遗漏，不重复替换。系统代理/路由、客户端替换、Cloud 部署不属于本计划的默认代码实施范围。

验收：隔离数据库连续两次运行无重复新增、既有 ID/来源关系/已读/收藏/baseline 保留；失败不推进成功状态；真实 Cloud 未验收时只记录已通过的本地范围，不登记为云支持。

### B6–B7：扩大覆盖

- P2 按实际 DOM 模板分组，不按域名批量猜配置。先选一个正常、一个空栏目及一个特殊日期/附件样本作为模板控制组，再每批验证 5–10 个栏目。
- 先处理 30 个 P2 失败栏目中的导航污染/空结果，复用公共修复降低后续成本。127 个部分通过栏目按其剩余标签处理，不为每个站点复制一个 parser 文件。
- P3 先处理可访问且归属明确的公开通知。`jdgz.jlu.edu.cn` 证书问题列为站点侧/环境阻塞，`lib.jlu.edu.cn` robots 禁止不继续抓取；不能把等待外部修复当代码任务已完成。
- 15 个受阻入口、44 个未发现栏目的入口、305 条官网未知机构分别管理；从官方目录、单位自证页面和官方关联页补证，不猜子域名、不把“没找到”改成“无需适配”。

## 4. 每批必须产出的东西

1. 最小代码差异及其问题复现 fixture，列明复用的既有未提交修复。
2. 逐栏验收记录：原 URL、来源/栏目、检查时间、代码指纹、执行环境、原因、样本 URL、列表/详情/附件/分页证据。
3. 新运行的兼容性结果和旧快照对照，区分修复、仍受阻、暂未验证和能力范围变化；不覆盖原始审计记录。
4. 候选来源配置及准入结论。只有内容和对应运行环境通过，才在后续明确范围内逐条变更正式 sources.yaml，保留 code/source identity 与数据库兼容性。
5. 回滚边界：规则按模板/配置小批启用；回滚本批代码或对应配置，不整仓 reset/checkout、不重置数据库、不删除用户其他工作。

## 5. 测试与停止条件

后端每个实现批次运行 `backend/.venv/Scripts/python.exe -m pytest`，隔离副本或环境必须明确排除正式 `.env` 与资料目录。先跑变更相关 fixture/安全/持久化回归，再跑完整后端测试；记录实际通过、失败和跳过数及理由。计划初稿没有改代码或运行测试，已实施批次的实际结果以对应报告为准。
