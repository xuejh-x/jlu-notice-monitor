## 2. 详情复核与流量边界

- 默认详情复核间隔 **24 小时**，每来源每轮最多 **5 条列表未变化的通知**，复核请求前默认等待 **1 秒**。原有来源并发、HTTP 重试、单来源执行时间和保留期限规则继续有效，没有新增全站遍历。
- 成功详情时间与列表出现时间分开保存。普通“再次看到列表条目”不会推迟详情复核。
- 到期条目按上次尝试时间排序。失败不建立成功基线，同时排在其他更久未尝试条目之后，避免固定的前几条失败长期占满预算。
- 检查点存储在既有 `AppState` 表，与成功详情、附件和更新记录在同一事务中提交；回滚不保存新成功基线。保留期清理同时删除对应检查点。
- Cloud feed 已携带详情的条目直接比较，不受上述额外网站详情请求预算影响；RSS/API 已携带且发生变化的正文也不会被列表元数据判断吞掉。未增加客户端直接访问学校的执行路径。
- 同一来源关系的身份变动成功后迁移附件归属，不凭列表出现先改检查点。SQLite 删除后复用通知 ID 时不会继承旧通知的检查点。写入检查点时刷新已有会话缓存；支持行锁的数据库使用行锁读取已有检查点，但本次没有真实 PostgreSQL 验收。

新增设置均有范围校验，无需修改正式来源 YAML：

| 环境变量 | 默认值 | 允许范围 |
| --- | ---: | --- |
| `JLU_DETAIL_RECHECK_INTERVAL_SECONDS` | 86400 | 3600–604800 秒 |
| `JLU_DETAIL_RECHECK_MAX_PER_SOURCE` | 5 | 1–20 条 |
| `JLU_DETAIL_RECHECK_DELAY_SECONDS` | 1.0 | 0–10 秒；本次假来源测试设为 0 |

24 小时是进入待复核队列的间隔，**不是所有通知都在 24 小时内完成更新的保证**。到期积压、运行频率、错误与来源时间上限会影响实际复核时间。复核范围只包括当前受列表页数、数量和保留期限制所返回的条目；已经离开列表范围的历史通知没有新增扫描。

## 3. 附件快照与兼容性

内部候选增加 `attachments_complete` 证据标志，默认是部分结果，并从序列化中排除。对外附件仍是 `filename / url / type`；通知与来源正文哈希仍沿用原有语义，没有修改数据库表结构或运行正式库迁移。

完整快照仅适用于识别到的静态 VSB 正文表单、受支持的 WordPress 文章范围，或明确提供附件字段的 Cloud feed 条目。动态脚本/嵌入、未提取的显式或文件类型链接（包括正文范围外的文件入口）、畸形链接、达到 50 条边界、安全校验丢弃的引用，以及任意自定义内容选择器，都按部分结果处理。完整表示该受支持范围内的附件引用快照，不表示文件可下载或内容完整。

- 完整快照允许移除本来源此前贡献、且没有其他来源贡献的旧引用；部分结果保留此前引用并合并本次安全提取的结果。
- 文件名和类型变化会更新现有附件行，并使通知产生一次版本变化；正文和附件同时变化也只增加一次版本。
- 附件顺序变化或相同引用重复出现，不增加版本。
- 旧来源首次建立成功详情检查点时，如果实际正文、日期和附件没有变化，不把空的尝试标记误认为“此前没有附件”，不会凭建立检查点增加版本。
- 同一 URL 有多个来源贡献时，使用稳定的展示选择，主通知来源优先；移除某一来源的贡献不会清掉其他来源的附件。
- 附件更新会推进通知更新时间，使公开 feed 的增量查询可以返回该通知。已加载的附件集合会失效刷新，避免同一会话继续输出已移除引用。

**保留边界：**修复前已有、无法证明归属的附件引用保守保留；检查点损坏或身份不符时同样不据此删除旧附件。部分解析结果、未识别的动态附件入口也不授权删除。同一 URL、文件名和类型完全不变但服务器替换了文件字节，本次不能识别；本板块未增加附件下载、内容哈希或可用性验证。
