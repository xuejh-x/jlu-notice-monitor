## 4. 本批规则修复

只修改审计辅助模块 `backend/app/services/attachment_validation.py`，没有修改来源抓取执行策略、数据库 schema、API、UI 或正式来源配置。

1. 识别 PDF、图片、Office、ZIP/RAR/7z 等已知 MIME 家族与实际文件签名的冲突。二进制 PDF 被标为 JPEG/文本，或 ZIP 被标为 PDF，不再判为文件前缀通过。
2. 容器签名不能覆盖明确的 Office MIME 与链接类型冲突。例如同为 ZIP 容器，响应明确标 DOCX、链接却标 XLSX时保留类型冲突，不宣称已验证 XLSX。
3. HTTP 206 提供 `Content-Range` 时，必须能证明从字节零开始，且声明范围基本自洽；非零起点、无效范围或范围与有限样本矛盾时不判为文件前缀通过。历史证据未保存该头的情况标记缺失，不补造其值。
4. 继续保留验证码/登录/校园网限制、HTML 下载页、空响应、类型冲突和未知前缀分类；`complete_download_verified` 始终为 false。无需仅凭响应头或扩展名就接受文件。

修复前 9 个反向控制用例失败，修复后通过。**它们是验收器误判风险的可复现测试，不是发现了 9 个真实损坏附件**；已有 25 个实测端点重审未改变分类。[修复前日志](jlu-fix-b5-d/regression-before-tests.log)、[最小应用改动](jlu-fix-b5-d/application-changes.diff)。
