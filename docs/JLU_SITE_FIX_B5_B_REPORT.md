## 3. 代码修复及可复用规则

涉及 `backend/app/parsers/html.py` 与 `backend/app/sources/generic.py`：

1. 共享 `list_publication_date`：明确“发布日期 / 发布时间 / 发表时间”优先；只有“更新时间 / 更新日期 / 修改时间”等标记时返回缺失，不再填入发布日期。默认解析和自定义日期选择器保持一致。
2. 同一日期节点先出现更新日期、后出现明确发布日期时，采用明确的发布值；`time[datetime]` 属性不能遮住可见的更新时间标签。
3. 保留无标签列表日期、VSB 分拆日历卡及详情列表日期回退的既有行为；不批量抹掉已有库日期。因此招生网的无标签列表日期仍能被解析，但审计明确判定其发布语义未确认，不凭解析值准入。
4. 独立审计器只采信文章范围内明确的发布标记，或指定的文章发布元数据；更新时间、正文活动/截止日期、通用网页日期不能证明发布。相互冲突或无效的发布证据不判通过。该审计规则不新增 API 字段或改变正式详情回退契约。

可复用 CMS 规则是 VSB 列表日历卡 + 文章标题/正文/附件范围解析；`.arc-info` 的“更新时间”仅作更新证据。不能把整个 YZB 模板统一注册为发布日期已验证模板。

复现依据：[修复前失败日志](jlu-fix-b5-b/regression-before-tests.log)、[最小应用改动](jlu-fix-b5-b/application-changes.diff)。16 个新增回归用例覆盖更新标签、发布/更新混排、datetime 属性、实际招生 fixture、正文日期误用、发布元数据冲突与无效日期。
